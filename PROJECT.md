# AI Dev Workflow - Fabrica de Software com IA

## Objetivo

Construir, testar, documentar e aperfeicoar um workflow integrado de desenvolvimento de software assistido por Inteligencia Artificial.

O objetivo e permitir que uma necessidade descrita em linguagem natural seja progressivamente transformada em uma aplicacao profissional, funcional, testada, versionada, documentada e publicada na internet.

## Fluxo principal

USUARIO
-> ChatGPT Project
-> GitHub
-> Antigravity IDE + Codex
-> Testes e revisao
-> GitHub
-> CI/CD
-> Deploy e hospedagem
-> Aplicacao publicada

Fluxo conceitual:

IDEIA
-> REQUISITOS
-> PLANO
-> CODIGO
-> TESTES
-> REVISAO
-> GITHUB
-> DEPLOY
-> SOFTWARE FUNCIONANDO

## Papel das ferramentas

### ChatGPT

Atua como:

- coordenador geral;
- arquiteto de solucoes;
- Product Manager / Product Owner assistente;
- analista de requisitos;
- planejador;
- decompositor de tarefas;
- organizador do workflow;
- responsavel pela documentacao;
- revisor de decisoes tecnicas;
- tradutor de ideias em especificacoes executaveis.

### GitHub

Atua como:

- fonte oficial do codigo;
- historico de alteracoes;
- sistema de controle de versao;
- ponto central para branches, commits, pull requests, releases e CI/CD.

### Antigravity IDE

Ambiente principal para trabalhar diretamente nos arquivos, executar o projeto, implementar funcionalidades, testar e corrigir codigo.

### Codex

Atua principalmente como:

- engenheiro de software;
- implementador de tarefas;
- revisor de codigo;
- solucionador de bugs;
- executor de refatoracoes;
- criador de testes;
- auditor tecnico.

### Google Antigravity 2.0

Sera introduzido progressivamente como camada de orquestracao de agentes depois que o workflow basico estiver funcionando corretamente.

### Gemini

Ferramenta complementar para situacoes em que apresente vantagem em:

- pesquisa;
- grandes contextos;
- documentacao;
- planejamento;
- revisao;
- exploracao de alternativas;
- integracao com o ecossistema Google.

## Principios do projeto

1. Simplicidade antes de complexidade.
2. Uma etapa pratica por vez.
3. Git e GitHub desde o inicio.
4. Tarefas pequenas, compreensiveis e testaveis.
5. Documentacao como memoria persistente.
6. Nenhuma credencial ou segredo diretamente no codigo.
7. Priorizar ferramentas gratuitas ou ja disponiveis.
8. Evitar duplicidade de ferramentas.
9. Deploy deve ser considerado desde o inicio.
10. Automatizar somente depois que o processo manual estiver funcionando.
11. Uma IA pode construir e outra revisar.
12. Toda aplicacao deve ser testavel, documentada e manutenivel.

## Regra fundamental de execucao

Durante a construcao pratica do workflow:

- executar somente o passo atual;
- explicar o que esta sendo feito;
- explicar por que esta sendo feito;
- fornecer o comando exato;
- informar o resultado esperado;
- verificar o resultado;
- corrigir erros antes de avancar;
- somente seguir para o proximo passo apos confirmacao.

## Estrategia de custos

Prioridade:

gratuito
-> incluido nas assinaturas atuais
-> open source
-> baixo custo
-> pago somente quando necessario

Toda nova ferramenta deve apresentar beneficio concreto antes de ser adicionada ao workflow.

## Fonte unica de verdade

O repositorio deve conter documentacao suficiente para que humanos e agentes de IA compreendam o projeto sem depender exclusivamente do historico das conversas.

Documentos principais planejados:

- README.md
- PROJECT.md
- REQUIREMENTS.md
- ARCHITECTURE.md
- TASKS.md
- CHANGELOG.md
- DECISIONS.md
- AGENTS.md
- .env.example

Outros documentos poderao ser adicionados conforme a necessidade de cada aplicacao.

## Criterio de conclusao

Uma aplicacao nao sera considerada concluida apenas porque o codigo foi escrito.

Ela devera, conforme aplicavel:

- executar sem erros criticos;
- cumprir os requisitos;
- possuir interface funcional;
- ser responsiva;
- possuir persistencia de dados quando necessaria;
- possuir seguranca minima;
- possuir testes essenciais;
- estar versionada;
- estar documentada;
- possuir estrategia de recuperacao;
- estar publicada;
- possuir endereco acessivel;
- permitir manutencao futura.
